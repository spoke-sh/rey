# ADR 0023: Workspace Workload Packages

- Status: Accepted; self-declared admission superseded by ADR 0049
- Date: 2026-08-09
- Extends: [ADR 0015](0015-workload-centered-product.md)
- Narrows: [ADR 0016](0016-first-workload-slice.md)

## Context

The first executable workload slice compiled its graphs and scenarios into
`rey-runtime`. That proved deterministic execution, typed deltas,
qualification, and the four workload commands, but it accidentally made
conformance fixtures look like the user's workload portfolio. It also hid the
most important authorship boundary: a coding harness should propose workload
graphs and scenarios, while Rey should validate, execute, compare, and retain
them.

A scenario can be generated by a harness without becoming mutable test output.
Once admitted, it is a frozen oracle. A graph proposer cannot rewrite that
oracle during a failing campaign and then claim convergence.

## Decision

The default workload catalog is a workspace package catalog rooted at
`workloads/`. Each immediate child package contains `workload.yaml` with schema
`rey.workload-package.v1`. The package binds:

- exact workload, graph, node, operation, port, and scenario identities;
- a candidate compute graph;
- a required/optional scenario suite and expected UTF-8 outputs;
- proposal kind, producer, producer revision, generated artifact roles, and
  generation inputs; and
- accepted admission state with a frozen scenario oracle.

Package discovery is read-only, sorted, bounded by package count and document
bytes, confined to the workspace-relative catalog root, and rejects symlinked
package paths, duplicate workload ids, unknown fields, unsupported operations,
and incomplete generation provenance. The initial package schema deliberately
admits only UTF-8 ports and the exact `trim` and `uppercase` operation
contracts. Broader values, mining operations, fixtures, and effects require
explicit package-schema extensions rather than permissive deserialization.

The exact package path and source-byte digest form a proposal contract bound
into the workload semantic identity. Changing graph, suite, admission, or
generator provenance therefore makes retained qualification stale.

Compiled workloads are no longer the default portfolio. They remain available
only through `--catalog conformance` and are visibly classified as
`BUILT-IN CONFORMANCE` or `BUILT-IN SYSTEM`. They test Rey's runner and system
operations; they are not evidence that a user workload was generated.

The package boundary imports an already generated and accepted package. ADR
0024 adds the preceding creation-request handoff without launching a coding
harness inside Rey. The harness may generate both graph and
scenario suite, but the suite is frozen before deterministic execution. Rey
alone runs the graph, computes directed deltas, derives qualification, and
retains results.

## Consequences

- `rey workloads list|test|run|status` resolve workspace packages by default
  and expose origin, package path, source digest, generator, and oracle state.
- Structured list, status, test, and run envelopes retain catalog and
  provenance alongside runtime artifacts.
- An empty workspace catalog can be listed, but testing or selecting a missing
  workload fails explicitly.
- Existing runner fixtures remain useful without occupying the product
  portfolio.
- A bounded creation request is now defined by ADR 0024; attention binding,
  harness response validation, and re-mining remain the next steps. Package
  admission is the deterministic receiving boundary.
